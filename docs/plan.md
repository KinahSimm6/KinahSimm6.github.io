# Project Plan

## Project Overview

The goal of this project is to create and publish a simple two-page personal website using HTML and CSS. The completed project will include a homepage, an About page, consistent styling, project documentation, and a public GitHub repository.

## Work Breakdown Structure (WBS)

### 1. Project Planning
- Define the purpose of the website.
- Identify the desired results and project exclusions.
- Complete the project scope statement.
- Identify potential project risks.

### 2. Website Development
- Create `index.html`.
- Create `about.html`.
- Create `style.css`.
- Add navigation between the homepage and About page.
- Add a link to my GitHub profile.
- Apply consistent styling to both pages.

### 3. Testing and Review
- Review both HTML pages for errors.

- Test the navigation between pages.
- Confirm the stylesheet works on both pages.
- Test all links.
- Review the website for readability and organization.

### 4. Documentation
- Revise and complete `scope.md`.
- Complete `plan.md`.
- Complete `retrospective.md`.
- Update `README.md` with the project purpose, live website link, and documentation links.

### 5. Publication and Submission
- Commit all project files to GitHub.
- Publish the website using GitHub Pages.
- Confirm both pages render correctly in the browser.
- Take screenshots of both live website pages.
- Create a ZIP file containing all project files.
- Submit the required links, screenshots, code, and ZIP file.

## TAME Risk Analysis

### Risk: Health and Availability

During this project, an unexpected medical situation affected the amount of time and energy I could consistently dedicate to coursework. Because the course is only eight weeks long and I am taking multiple CMPA courses at the same time, losing even a small amount of working time could have a major effect on the project schedule.

**Impact:** 5/5  
**Probability:** 4/5  
**Risk Score:** 20/25 - High

### Mitigation Strategy

To reduce this risk, I can break large assignments into smaller and more manageable tasks, begin major projects earlier, and work during periods when my symptoms are manageable. I can also regularly review upcoming deadlines instead of waiting until an assignment is due and communicate with my professor when a medical issue significantly affects my ability to complete coursework.

## Project Monitoring

Progress will be monitored by comparing completed tasks with the Work Breakdown Structure and checking the GitHub repository to make sure all required files are present. Before final submission, I will compare the completed repository against the project requirements to identify any missing files or unfinished tasks.
